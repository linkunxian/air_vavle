# ESP32-S3 三路独立脉冲网页控制与巴法云上报

U7、U8、U9 上电默认均为 **1 Hz、停止**。三路各有一个 MCPWM 硬件定时器，可以只启用一路，也可以让多路以不同频率同时运行。使用开发板自带的网页操作，无需四键面板。

## 打开控制网页

1. 在 ESP-IDF 6.0.2 终端运行 `idf.py menuconfig`。进 **Air valve / Bemfa**，填开发板要连接的 2.4 GHz Wi-Fi SSID 和密码。只控制网页可以不填巴法云私钥和主题。
2. 可设置 **Local web control password**（8–64 个不含空格的可打印 ASCII 字符）。留空时，开发板每次开机后生成临时密码，通过串口的 `Web control password for this boot:` 打印。这个密码与 Wi-Fi 密码、巴法云私钥无关。
3. 执行 `idf.py build`、`idf.py -p COMx flash monitor`，将 `COMx` 替换成实际端口。拿到 Wi-Fi IP 后，串口会打印 `Control page: http://.../`。让手机或电脑和开发板处于同一局域网，在浏览器打开这个 `http://` 地址，不要直接打开源码里的 HTML 文件。如果 DHCP 改了 IP，用串口里最新的地址。
4. 网页输入控制密码，在对应通道选 1–6 Hz，点**应用频率**，再点该路的**启动**。新频率从该路下一次脉冲开始生效。点**停止**后，正在输出的 50 ms 脉冲正常结束，不再启动下一次脉冲；以网页显示「已停止」为准。
5. 点对应通道的**计数清零**并确认，只清该路累计值，不改变启停或频率。运行时清零，下一次脉冲从 1 继续计数；想让数值保持为 0，就先停该路再清零。

网页使用局域网 HTTP，请只在可信网络使用，不要做路由器端口映射或对公网开放。**关网页或断开 Wi-Fi 不会自动停机。** 做带负载测试时应保留现场断电手段，不能把网页当作紧急停机开关。

| 通道 | 负载 | FI（50 ms 正向驱动） | BI（始终低电平） |
| --- | --- | --- | --- |
| U7 | 气泵 | GPIO12 | GPIO13 |
| U8 | 电磁阀 | GPIO14 | GPIO15 |
| U9 | 风扇 | GPIO16 | GPIO17 |

关断期间，对应路的 FI 和 BI 均为低电平。不使用内部 kHz PWM。每路只在自己的脉冲开始时加 1。计数代表驱动脉冲，不代表气泵或风扇已经机械转动；50 ms 可能短于它们的启动时间。带负载前先测空载波形；多路同时运行时，确认电源、供电线路和驱动器能承受负载的峰值电流。

## 可选：巴法云上报

- 在 **Air valve / Bemfa** 配置巴法云 MQTT 私钥和各路不同的 MQTT 主题，如 U7 `pumpcount`、U8 `valvecount`、U9 `fancount`，不加 `/up`。私钥等配置会进入本地固件，不应公开分享。
- 固件默认每 5 秒向每个已配置的 `<主题原名>/up` 上报对应路的十进制累计值。某路清零后，下次上报会读取该路清零后的最新值。MQTT 重连后发送各路最新总数，不补发旧消息。SNTP 只用于校验云端 TLS 证书，不影响网页控制。
- 停止、改频、关网页或断网都不会清零；重启或掉电会清零。

## 台架验收

1. 用逻辑分析仪同时测 GPIO12、GPIO14 和 GPIO16。只点 U8 **启动**，确认只有 GPIO14 输出脉冲。然后以不同频率启动 U7，确认 U8 不受影响；停止 U8 后，U7 应继续运行。
2. 每路以自己的首个上升沿为 `t = 0`。在设备标称时间 `0 ≤ t < 1000 ms` 内，每路上升沿数应等于该路所选的频率。下一秒边界上的上升沿不计入前一秒；实测边界应考虑晶振和仪器误差。
3. 确认各路高电平为 50 ms，所有 BI 保持低电平。MCPWM 时钟为 64 kHz，3 Hz 和 6 Hz 的周期在相邻的两个计数刻度之间分配，累计一秒恰好用 64,000 个刻度。
4. 清零已停止的 U8，确认 U8 保持 0，U7 继续计数；运行时清零 U9，确认 U9 不停机并从零重新累计。断开再恢复 Wi-Fi 后，已配置的主题应收到对应路的最新累计值。
